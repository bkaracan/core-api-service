Spring Boot 4.1.1 Kurumsal JPA Entity & Repository Standartları

Büyük ölçekli, güvenlik odaklı ve regülasyona tabi kurumsal mimariler için tasarlanmış veri kalıcılığı (persistence) standartları. IDOR saldırılarını önleyen Dual-ID deseni, Spring Security ile tam denetim izi (Audit Trail), Hibernate 6 mantıksal silme (Soft Delete), eşzamanlı çakışmaları engelleyen Optimistic Locking ve N+1 krizlerini bitiren @EntityGraph kuralları.

AŞAMA 1

Kurumsal Mimari İlkeler & Güvenlik Standartları

Kurumsal sistemlerin veri bütünlüğü, izlenebilirliği ve güvenliği için belirlenen 5 temel kural.

1. Dual-ID Deseni (IDOR Koruması & Performans)
Veritabanı içi ve dış dünya ID'leri birbirinden kesin olarak ayrılır:
  • İç ID (Long id): PK, Clustered Index ve Foreign Key performansı içindir. Asla API'ye sızdırılmaz!
  • Dış ID (UUID publicId): REST API URL'lerinde (/api/v1/orders/{publicId}) kullanılır. Ardışık olmadığı için IDOR açıklarını ve veri taramayı imkansız kılar.
2. Tam Denetim İzi (Kim & Ne Zaman?)
KVKK, GDPR, SOC2 ve finansal regülasyonlar için her işlem mühürlenir:
  • createdAt ve updatedAt (Zaman damgası).
  • createdBy ve lastModifiedBy (Kullanıcı mühürü).
  • Spring Security context'inden aktif JWT kullanıcısını SecurityAuditorAware otomatik çeker.
3. Mantıksal Silme (Soft Delete & @SQLRestriction)
Veriler asla fiziksel olarak (DELETE FROM ...) silinmez:
  • deleted = true, deletedAt = NOW() ve deletedBy ile arşivlenir.
  • Hibernate 6 @SQLRestriction("deleted = false") ile silinmiş kayıtlar tüm sorgulardan otomatik filtrelenir.
  • Yanlışlıkla veri silinmesi engellenir ve geri kurtarma (restore) desteklenir.
4. Concurrency Kontrolü (@Version Optimistic Locking)
Eşzamanlı isteklerde ezilen verileri (lost updates) önler:
  • Her güncellemede version sayısı 1 artırılır.
  • İki kullanıcı aynı anda kaydı değiştirmeye çalışırsa ikincisi ObjectOptimisticLockingFailureException alır.
  • Stok, bakiye ve profil güncellemelerinde veri tutarlılığı garanti altına alınır.

JPA Auditing & Spring Security Entegrasyonu

Aktif JWT oturumundan kullanıcıyı yakalayan SecurityAuditorAware ve JPA Auditing konfigürasyonu.

SecurityAuditorAware.java Spring Component
package com.enterprise.coreapi.common.config;

import org.jspecify.annotations.NonNull;
import org.springframework.data.domain.AuditorAware;
import org.springframework.security.authentication.AnonymousAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;

import java.util.Optional;

/**
 * Spring Security Context üzerinden aktif kullanıcı bilgisini (JWT Subject)
 * yakalayarak JPA @CreatedBy ve @LastModifiedBy alanlarına otomatik enjekte eder.
 */
@Component("securityAuditorAware")
public class SecurityAuditorAware implements AuditorAware<String> {

    public static final String SYSTEM_USER = "SYSTEM";

    @Override
    @NonNull
    public Optional<String> getCurrentAuditor() {
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();

        if (authentication == null || !authentication.isAuthenticated() || authentication instanceof AnonymousAuthenticationToken) {
            return Optional.of(SYSTEM_USER);
        }

        String username = authentication.getName();
        return (username != null && !username.isBlank()) ? Optional.of(username) : Optional.of(SYSTEM_USER);
    }
}

Kurumsal BaseEntity Mimarisi

Dual-ID, Full Auditing, Soft-Delete, Optimistic Locking ve Proxy-Safe equals/hashCode bileşenleri.

BaseEntity.java Enterprise MappedSuperclass
package com.enterprise.coreapi.common.entity;

import jakarta.persistence.*;
import lombok.Getter;
import lombok.Setter;
import org.hibernate.Hibernate;
import org.springframework.data.annotation.CreatedBy;
import org.springframework.data.annotation.CreatedDate;
import org.springframework.data.annotation.LastModifiedBy;
import org.springframework.data.annotation.LastModifiedDate;
import org.springframework.data.jpa.domain.support.AuditingEntityListener;

import java.time.Instant;
import java.util.Objects;
import java.util.UUID;

@Getter
@Setter
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class BaseEntity {

    /**
     * 1. İç Veritabanı Birincil Anahtarı (Internal PK).
     * Yalnızca DB indeksleme ve foreign key performansı içindir. Asla API'ye verilmez!
     */
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    /**
     * 2. Dış Dünyaya Açık Genel Kimlik (Public Business Key / External ID).
     * API endpoint'lerinde (/api/v1/resources/{publicId}) kullanılır. IDOR saldırılarını önler.
     */
    @Column(name = "public_id", nullable = false, unique = true, updatable = false)
    private UUID publicId = UUID.randomUUID();

    /**
     * 3. Eşzamanlılık Kontrolü (Optimistic Locking).
     */
    @Version
    @Column(nullable = false)
    private Long version;

    // --- 4. AUDITING ALANLARI (Kim & Ne Zaman) ---

    @CreatedDate
    @Column(name = "created_at", nullable = false, updatable = false)
    private Instant createdAt;

    @LastModifiedDate
    @Column(name = "updated_at", nullable = false)
    private Instant updatedAt;

    @CreatedBy
    @Column(name = "created_by", nullable = false, updatable = false, length = 100)
    private String createdBy;

    @LastModifiedBy
    @Column(name = "last_modified_by", nullable = false, length = 100)
    private String lastModifiedBy;

    // --- 5. SOFT DELETE ALANLARI (Mantıksal Silme) ---

    @Column(name = "deleted", nullable = false)
    private boolean deleted = false;

    @Column(name = "deleted_at")
    private Instant deletedAt;

    @Column(name = "deleted_by", length = 100)
    private String deletedBy;

    public void markDeleted(String deletedBy) {
        this.deleted = true;
        this.deletedAt = Instant.now();
        this.deletedBy = deletedBy;
    }

    public void restore() {
        this.deleted = false;
        this.deletedAt = null;
        this.deletedBy = null;
    }

    /**
     * Hibernate Proxy Uyumlu equals Implementasyonu:
     * ByteBuddy runtime proxy nesneleri için Hibernate.getClass(this) kullanılır.
     * Değişmez iş anahtarı publicId üzerinden karşılaştırılır.
     */
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || Hibernate.getClass(this) != Hibernate.getClass(o)) return false;
        BaseEntity that = (BaseEntity) o;
        return publicId != null && Objects.equals(publicId, that.publicId);
    }

    @Override
    public int hashCode() {
        return Hibernate.getClass(this).hashCode();
    }
}

Domain Modelleri & Hibernate 6 @SQLRestriction

Otomatik soft-delete filtreleme, indeksleme stratejileri ve katı LAZY ilişkiler.

Product.java Enterprise Entity
package com.enterprise.coreapi.entity;

import com.enterprise.coreapi.common.entity.BaseEntity;
import jakarta.persistence.*;
import lombok.*;
import org.hibernate.annotations.SQLRestriction;
import java.math.BigDecimal;

@Entity
@Table(name = "products", indexes = {
        @Index(name = "idx_product_public_id", columnList = "public_id", unique = true),
        @Index(name = "idx_product_sku", columnList = "sku", unique = true),
        @Index(name = "idx_product_category", columnList = "category_id")
})
@SQLRestriction("deleted = false") // Hibernate 6: Silinmiş kayıtları tüm sorgularda otomatik filtreler
@Getter
@Setter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Product extends BaseEntity {

    @Column(nullable = false, length = 150)
    private String name;

    @Column(nullable = false, unique = true, length = 50)
    private String sku;

    @Column(nullable = false, precision = 12, scale = 2)
    private BigDecimal price;

    @Column(nullable = false)
    private boolean active = true;

    /**
     * KRİTİK STANDART: FetchType.LAZY zorunludur!
     */
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "category_id", nullable = false, foreignKey = @ForeignKey(name = "fk_product_category"))
    private Category category;
}

Spring Data Repository & Public ID Sorgu Mimarisi

Dış dünyadan gelen UUID publicId aramaları ve @EntityGraph ile N+1 çözümleri.

ProductRepository.java Spring Data JpaRepository
package com.enterprise.coreapi.repository;

import com.enterprise.coreapi.dto.projection.ProductSummaryProjection;
import com.enterprise.coreapi.entity.Product;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.EntityGraph;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.JpaSpecificationExecutor;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.Optional;
import java.util.UUID;

@Repository
public interface ProductRepository extends JpaRepository<Product, Long>, JpaSpecificationExecutor<Product> {

    /**
     * API İstemcilerinden gelen UUID publicId ile tekil getirme (IDOR güvenli).
     * @EntityGraph sayesinde ilişkili Category tek SQL JOIN ile anında çekilir.
     */
    @EntityGraph(attributePaths = {"category"})
    Optional<Product> findByPublicId(UUID publicId);

    boolean existsBySku(String sku);

    /**
     * ULTRA PERFORMANSLI RECORD PROJECTION (Sayfalı):
     */
    @Query("""
        SELECT new com.enterprise.coreapi.dto.projection.ProductSummaryProjection(
            p.publicId,
            p.name,
            p.sku,
            p.price,
            c.name
        )
        FROM Product p
        JOIN p.category c
        WHERE p.active = true
        """)
    Page<ProductSummaryProjection> findAllSummaryProjections(Pageable pageable);
}

Kurumsal Anti-Pattern Karşılaştırmaları

Güvenlik ve mimari seviyede yapılan 3 kritik hata ve kurumsal çözümler.

❌ YANLIŞ: Ardışık Long ID'nin API'ye Açılması (IDOR)
// GET /api/v1/orders/1001
// Saldırgan ardışık ID'leri tarayarak (1002, 1003...)
// tüm müşterilerin siparişlerini ve ciroyu öğrenebilir!
IDOR saldırıları ve işletme metriklerinin sızdırılması en yaygın API güvenlik zaafiyetlerindendir.
✅ DOĞRU: Dual-ID Deseni (UUID publicId)
// GET /api/v1/orders/018e3a2b-9f21-789a-bc01-def456789abc
// İçeride Long PK performansı korunur;
// Dışarıda tahmin edilemez UUID ile veri taranamayacak hale gelir.
İçeride hızlı indeks ve JOIN avantajı, dışarıda üst düzey API güvenliği sağlanır.
❌ YANLIŞ: Fiziksel Silme (DELETE FROM ...)
@DeleteMapping("/{id}")
public void delete(@PathVariable Long id) {
    productRepository.deleteById(id); // FİZİKSEL SİLME!
    // Geçmiş siparişlerde referans bozulur, denetim izi kaybolur!
}
Kurumsal ERP, Fintech ve E-ticaret sistemlerinde fiziksel silme yasal ve teknik olarak kabul edilemez.
✅ DOĞRU: Soft Delete & @SQLRestriction
@DeleteMapping("/{publicId}")
public void delete(@PathVariable UUID publicId) {
    product.markDeleted(currentUser);
    // Kayıt korunur, @SQLRestriction ile otomatik filtrelenir.
}
İlişkisel bütünlük korunur, muhasebe/sipariş geçmişi kaybolmaz ve geri kurtarma desteklenir.
❌ YANLIŞ: Denetim İzi (Audit Trail) Tutulmaması
// Tabloda sadece veri var: "price = 50.00"
// "Fiyatı kim 50 TL'ye düşürdü? Ne zaman değişti?"
// sorusunun cevabı veritabanında YOK!
SOC2, KVKK, GDPR ve ISO denetimlerinde sistem doğrudan uygunsuzluk alır.
✅ DOĞRU: Spring Security AuditorAware Mühürü
// createdAt: 2026-10-01 10:15
// createdBy: "user@enterprise.com"
// updatedAt: 2026-10-01 12:30
// lastModifiedBy: "manager@enterprise.com"
Her kayıt oluşturan ve son güncelleyen kullanıcıyla mühürlenir.

Kurumsal Mimari Kontrol Listesi (Checklist)

Entity ve Repository katmanlarını commit etmeden önce doğrulanması zorunlu 12 kural.

CHK-JPA-01 Kurumsal BaseEntity Kalıtımı Tüm entity sınıfları BaseEntity'den türetilmeli (id, publicId, version, audit ve soft delete alanları). Zorunlu

CHK-JPA-03 Spring Security AuditorAware createdBy ve lastModifiedBy alanları SecurityAuditorAware ile otomatik doldurulmalıdır. Zorunlu
CHK-JPA-04 Soft Delete & @SQLRestriction Fiziksel DELETE yasaklanmalı; @SQLRestriction("deleted = false") ile mantıksal silme uygulanmalıdır. Zorunlu
CHK-JPA-05 Optimistic Locking (@Version) Concurrency güvenliği ve lost update'leri önlemek için @Version tanımlanmalıdır. Zorunlu
CHK-JPA-06 Katı LAZY Fetching Kuralı @ManyToOne ve @OneToOne ilişkileri istisnasız fetch = FetchType.LAZY olmalıdır (EAGER yasaktır). Zorunlu
CHK-JPA-07 Lombok @Data Yasağı Entity sınıflarında asla @Data ve serbest @ToString kullanılmamalıdır. Zorunlu
CHK-JPA-08 Proxy-Safe equals/hashCode Hibernate.getClass(this) ve değişmez publicId kullanılarak proxy-safe eşitlik sağlanmalıdır. Zorunlu
CHK-JPA-09 N+1 Önleme (@EntityGraph) İlişkili nesneler çekilirken @EntityGraph veya JPQL JOIN FETCH kullanılmalıdır. Zorunlu
CHK-JPA-10 Record Tabanlı Projeksiyon Sadece okunacak listelemelerde doğrudan Java 21 record projeksiyonları döndürülmelidir. Zorunlu
CHK-JPA-11 @Transactional(readOnly = true) Veri okuma metotlarında dirty-checking snapshot'ı kapatılmalıdır. Zorunlu
CHK-JPA-12 İndeksleme Standartları public_id, sku ve foreign key alanları @Table(indexes = ...) ile indekslenmelidir. Zorunlu
