Standard Dependency Matrix (Spring Boot 4.1.1)

01 Core / Web Katmanı

  • Spring Data JPA spring-boot-starter-data-jpa

  • PostgreSQL Driver org.postgresql:postgresql

  • Flyway Migration flyway-core + flyway-database-postgresql

03 Observability & Diagnostics
  • Spring Boot Actuator spring-boot-starter-actuator

04 Dev Tools & Containers
  • Docker Compose Support spring-boot-docker-compose
    Uygulama başladığında compose.yaml üzerindeki PostgreSQL container'ını otomatik ayağa kaldırır.
  • Spring Boot DevTools spring-boot-devtools
    Hızlı otomatik yeniden başlatma (hot-restart), live reload ve geliştirme modu optimizasyonları.
05 API Documentation (OpenAPI)
pom.xml Eklentisi
  • Springdoc OpenAPI Starter WebMvc UI springdoc-openapi-starter-webmvc-ui
    Swagger UI v3 ve OpenAPI 3.1 JSON/YAML dokümantasyonunu otomatik üretir. Spring Boot 4.x ve Spring Framework 7 uyumlu sürümü ile pom.xml'e eklenir.
06 Modern Integration Testing
  • Testcontainers & PostgreSQL spring-boot-testcontainers
    Entegrasyon testlerinde H2 gibi in-memory yalancı veritabanları yerine gerçek PostgreSQL konteyneri çalıştırarak %100 güvenilir testler sağlar.

AŞAMA 2

Docker & PostgreSQL Entegrasyonu

Spring Boot 4.1.1 compose.yaml desteği ile yerel geliştirme ortamını sıfır konfigürasyonla ayağa kaldırın ve çok katmanlı (multi-stage) Dockerfile ile prodüksiyon imajı üretin.

compose.yaml (.env değişkenlerini otomatik okur)
services:
  postgres:
    image: 'postgres:16-alpine'
    container_name: 'core-api-postgres'
    environment:
      - POSTGRES_DB=${POSTGRES_DB:-core_api_db}
      - POSTGRES_USER=${POSTGRES_USER:-postgres}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-postgres}
    ports:
      - "${POSTGRES_PORT:-5432}:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-core_api_db}"]
      interval: 5s
      timeout: 5s
      retries: 5
      start_period: 10s

volumes:
  postgres_data:
    driver: local
.env.example (Depoda paylaşılan güvenli şablon)
# =====================================================================
# Database & Docker Configuration Template (.env.example)
# Bu dosya Git'e eklenir (yerel ozellestirmeler icin sablon niteligindedir).
# Gelistirici yerel ayarlarini ozellestirmek icin bunu kopyalayabilir:
#   Windows CMD: copy .env.example .env
#   Linux/Bash:  cp .env.example .env
# =====================================================================
POSTGRES_DB=core_api_db
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_PORT=5432
APP_PORT=8080
Dockerfile (Eclipse Temurin 21 JRE, Layered Jar, Non-Root User)
# =====================================================================
# Stage 1: Build & Dependency Caching (Java 21 LTS)
# =====================================================================
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace
COPY .mvn/ .mvn
COPY mvnw pom.xml ./
RUN ./mvnw dependency:go-offline -B
COPY src ./src
RUN ./mvnw clean package -DskipTests

# =====================================================================
# Stage 2: Extract Spring Boot Layered Jar (Spring Boot 3.3+ / 4.x tools)
# =====================================================================
FROM eclipse-temurin:21-jre-jammy AS extractor
WORKDIR /workspace
COPY --from=builder /workspace/target/*.jar app.jar
RUN java -Djarmode=tools -jar app.jar extract --layers --launcher --destination extracted

# =====================================================================
# Stage 3: Minimal, Hardened Production Runtime
# =====================================================================
FROM eclipse-temurin:21-jre-jammy
WORKDIR /app

# Güvenlik standardı: root olmayan kullanıcı oluştur
RUN groupadd -r spring && useradd -r -g spring spring && chown -R spring:spring /app
USER spring:spring

# Katmanları en az değişenden en sık değişene doğru kopyala (Docker Layer Caching)
COPY --from=extractor --chown=spring:spring /workspace/extracted/dependencies/ ./
COPY --from=extractor --chown=spring:spring /workspace/extracted/spring-boot-loader/ ./
COPY --from=extractor --chown=spring:spring /workspace/extracted/snapshot-dependencies/ ./
COPY --from=extractor --chown=spring:spring /workspace/extracted/application/ ./

EXPOSE 8080
ENTRYPOINT ["java", "-XX:+UseZGC", "-XX:+ZGenerational", "-Djava.security.egd=file:/dev/./urandom", "org.springframework.boot.loader.launch.JarLauncher"]
🚀
Spring Boot 4.1.1 Docker Compose Otomasyonu: Proje kök dizininde compose.yaml dosyası ve spring-boot-docker-compose bağımlılığı olduğunda, geliştirici doğrudan ./mvnw spring-boot:run (veya Windows CMD/PowerShell'de mvnw spring-boot:run) komutunu çalıştırdığında PostgreSQL konteyneri otomatik olarak ayağa kalkar ve bağlantı parametreleri uygulamaya dinamik olarak enjekte edilir. Manuel docker compose up çalıştırmaya gerek kalmaz.

# Linux / macOS / Git Bash:

Adım 2: .env Dosyasının İçeriğini İhtiyacınıza Göre Düzenleyin

Oluşturulan .env dosyasını VS Code, IntelliJ IDEA veya herhangi bir metin düzenleyici ile açarak değerleri yerel ortamınıza göre belirleyin:

Değişken Adı Örnek Değer Açıklama & Güvenlik Amacı
POSTGRES_DB core_api_db PostgreSQL üzerinde otomatik açılacak veritabanı adı.
POSTGRES_USER core_api_user Veritabanı yetkili servis kullanıcısı (Root 'postgres' yerine adanmış servis hesabı).
POSTGRES_PASSWORD p@ssw0rd_Guclu_123 Kritik Gizli Bilgi: Asla 'postgres' veya basit şifreler bırakmayın. Yalnızca yerelinizde kalacaktır.
POSTGRES_PORT 5432 Host makinede dinlenecek port. Bilgisayarınızda 5432 portu doluysa 5433 yapabilirsiniz.
APP_PORT 8080 Spring Boot REST API HTTP servis portu.
💡
Geliştirici Deneyimi (DevEx) & Out-of-the-Box Çalışma Güvencesi: compose.yaml ve application.yml dosyalarında ${POSTGRES_PASSWORD:-postgres} sözdizimi tanımlanmıştır. Bu sayede projeyi yeni indiren veya klonlayan bir geliştirici, henüz bir .env dosyası oluşturmamış olsa bile tek bir hata almadan doğrudan docker compose up veya ./mvnw spring-boot:run diyerek anında çalışmaya başlayabilir. Buradaki postgres parolası bir veri açığı değildir; yalnızca geliştiricinin kendi makinesindeki geçici Docker konteyneri için geçerlidir. Canlı/Production ortamında bu değer Kubernetes, CI/CD veya işletim sistemi ortam değişkenleri tarafından otomatik olarak ezilir.
AŞAMA 3

Konfigürasyon & Flyway Veritabanı Migrasyonu

Spring Boot 4.1.1 üretime hazır application.yml yapılandırması ve kurumsal Flyway SQL şema sürümleme standartları.

src/main/resources/application.yml (Spring Boot 4.1.1 Standart Yapılandırma) 
# =====================================================================
# Enterprise Spring Boot Configuration
# =====================================================================
server:
  port: 8080
  shutdown: graceful # Pod/Container durdurulurken aktif istekleri guvenle tamamla

spring:
  application:
    name: core-api-service

  # Java 21 Project Loom - Sanal Is Parcaciklari (Virtual Threads)
  threads:
    virtual:
      enabled: true

  # Docker Compose Destegi
  docker:
    compose:
      enabled: true
      file: compose.yaml
      lifecycle-management: start-and-stop

  # Veritabani ve HikariCP Baglanti Havuzu (Yerel DevEx Varsayilanlari & Canli Ortam Ezmesi)
  datasource:
    url: jdbc:postgresql://${POSTGRES_HOST:localhost}:${POSTGRES_PORT:5432}/${POSTGRES_DB:core_api_db}
    username: ${POSTGRES_USER:postgres}
    password: ${POSTGRES_PASSWORD:postgres}
    driver-class-name: org.postgresql.Driver
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5
      idle-timeout: 300000
      connection-timeout: 20000
      max-lifetime: 1200000

  # Spring Data JPA / Hibernate Standartlari
  jpa:
    open-in-view: false # Kritik: Anti-pattern ve sizintilari onlemek icin daima false!
    hibernate:
      ddl-auto: validate # Asla update/create degil; sema kontrolu sadece Flyway ile yapilir!
    show-sql: false
    properties:
      hibernate:
        format_sql: true
        default_batch_fetch_size: 25 # N+1 sorgu problemini engeller

  # Flyway Sema Surumleme
  flyway:
    enabled: true
    baseline-on-migrate: true
    locations: classpath:db/migration

# Observability: Actuator & Prometheus
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus,metrics
  endpoint:
    health:
      show-details: always
      probes:
        enabled: true # Kubernetes Liveness & Readiness destegi
  metrics:
    tags:
      application: ${spring.application.name}

# Springdoc Swagger UI Yapilandirmasi
springdoc:
  api-docs:
    path: /v3/api-docs
  swagger-ui:
    path: /swagger-ui.html
    operations-sorter: method
    tags-sorter: alpha
    display-request-duration: true
🔐
Kurumsal Konfigürasyon Hiyerarşisi, DevEx Fallback & Canlı Ortam Ezme Standardı:
  • Temel application.yml Daima Git'tedir: Bu dosya uygulamanın mimari iskeletini ve varsayılanlarını tanımlar. Kesinlikle .gitignore içine eklenmez. CI/CD testlerinin koşabilmesi için depoda bulunması zorunludur.
  • Yerel DevEx Fallback Mimarisi: username: ${POSTGRES_USER:postgres} ve password: ${POSTGRES_PASSWORD:postgres} sözdizimi, yerel geliştirmede geliştiricinin sıfır konfigürasyonla anında çalışmasını ("Works out of the box") garanti eder.
  • Canlı Ortam Önceliği (Environment Variable Precedence): Canlı (Production) veya Kubernetes ortamlarında, pod/container konfigürasyonuna POSTGRES_PASSWORD ve POSTGRES_USER ortam değişkenleri enjekte edilir. Spring Boot ve Docker Compose bu değişkenleri en yüksek öncelikle ele alır ve yerel fallback değerlerini tamamen geçersiz kılar.
  • İsteğe Bağlı Yerel Özelleştirme (.env): Geliştirici yerel portunu (örn. 5433) veya kendi yerel şifresini değiştirmek isterse kök dizindeki .env dosyasını kullanabilir. Bu dosya .gitignore ile korunur ve Git'e gitmez.
  • Docker Port Çakışmalarında compose.override.yaml: Geliştiricinin makinesinde 5432 portu doluysa ana compose.yaml değiştirilmez; compose.override.yaml ile port ezilir ve bu override dosyası depoya gönderilmez.

Flyway Versiyonlama & Örnek V1 Başlangıç Şeması

Flyway göç dosyaları src/main/resources/db/migration/ altında V{Sürüm}__{Açıklama}.sql isimlendirme formatına (aradaki iki alt çizgiye dikkat!) kesinlikle uymalıdır.

src/main/resources/db/migration/V1__init_schema.sql 
-- =====================================================================
-- Migration: V1__init_schema.sql
-- Standart Kurumsal Başlangıç Şeması (UUID, Audit, Optimistic Lock)
-- =====================================================================

-- 1. UUID Üretimi için pgcrypto eklentisini etkinleştir
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. Standart Kurumsal Varlık Tablosu (Örnek: app_user)
CREATE TABLE app_user (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    version BIGINT NOT NULL DEFAULT 0, -- Optimistic Lock (@Version)
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 3. Performans ve Arama İndeksleri
CREATE INDEX idx_app_user_email ON app_user(email);
CREATE INDEX idx_app_user_created_at ON app_user(created_at);

Testcontainers ile Gerçekçi Entegrasyon Testi

Spring Boot 4.1.1 ile gelen @ServiceConnection anotasyonu sayesinde, PostgreSQL container'ı için dinamik datasource URL veya credentials tanımlamaya gerek kalmaz.

src/test/java/com/enterprise/coreapi/CoreApiServiceApplicationTests.java
package com.enterprise.coreapi;

import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.testcontainers.service.connection.ServiceConnection;
import org.testcontainers.containers.PostgreSQLContainer;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@Testcontainers
class CoreApiServiceApplicationTests {

    // @ServiceConnection ile DataSource otomatik olarak bu konteynere bağlanır
    @Container
    @ServiceConnection
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine");

    @Test
    void contextLoads() {
        assertThat(postgres.isRunning()).isTrue();
    }
}
