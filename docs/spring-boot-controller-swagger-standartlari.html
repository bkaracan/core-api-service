Controller Katmanı & Swagger Standardizasyonu

Kurumsal ölçekli mikroservislerde HTTP protokol nesnelerinin (ResponseEntity, HttpStatus, ApiResponse) yalnızca Controller sınırında tutulması; Service katmanının saf iş mantığıyla korunması ve Controller sınıflarının tekrar eden Swagger kodlarından Bileşik Meta-Anotasyonlar ile arındırılması rehberi.

AŞAMA 1

HTTP Sınır İzolasyonu (Protocol Boundary Isolation)

Clean Architecture ve Domain-Driven Design prensiplerine göre katmanların sorumluluk sınırları.

┌─────────────────────────────────────────────────────────────────────────────┐ │ HTTP İSTEMCİSİ (Web, Mobil, Gateway) │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ HTTP JSON Request ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ 1. CONTROLLER KATMANI (HTTP Boundary Layer - Sınır Kapısı) │ │ - @PathVariable, @RequestParam, @RequestBody, @Valid doğrulamaları │ │ - ResponseEntity<ApiResponse<T>> veya ResponseEntity<PageResponse<T>> │ │ - HTTP Durum Kodları (200 OK, 201 CREATED, 204 NO CONTENT) │ │ - OpenAPI / Swagger Meta-Anotasyonları (@ApiGetResponse, @ApiCreateResponse)│ └──────────────────────────────────────┬──────────────────────────────────────┘ │ Saf Java Parametreleri / DTO ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ 2. SERVICE KATMANI (Pure Domain / Application Business Layer) │ │ - KESİNLİKLE org.springframework.http.* IMPORT EDEMEZ! │ │ - KESİNLİKLE ResponseEntity, HttpStatus veya ApiResponse DÖNEMEZ! │ │ - Yalnızca saf DTO'lar, Entity'ler veya Page<T> döner │ │ - Hata durumunda Domain Exception fırlatır (ResourceNotFoundException) │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ 3. REPOSITORY KATMANI (Persistence Layer - Spring Data JPA) │ └─────────────────────────────────────────────────────────────────────────────┘
🚫 Neden Service'te ResponseEntity Yasak?
Service metodunda ResponseEntity döndürülürse o metod HTTP protokolüne zincirlenir. Aynı servisi bir Kafka dinleyicisi, RabbitMQ kuyruğu, gRPC servisi veya arka plan zamanlanmış görevi (@Scheduled) çağıramaz hale gelir.
📦 Neden ApiResponse Controller'da?
ApiResponse<T> bir HTTP transfer zarfıdır. Servis katmanının görevi veriyi zarflamak değil; veriyi üretmek, doğrulamak ve iş kurallarını işletmektir. Zarflama kararı sunum (Controller) katmanına aittir.
🧹 Anotasyon Hijyeni
Her metoda tek tek 10 satır Swagger anotasyonu eklemek kodun okunmasını imkansızlaştırır ("Annotation Hell"). Kurumsal meta-anotasyonlar sayesinde 1 satır ile RFC 7807 dahil tüm yanıtlar standartlaşır.
AŞAMA 2

Doğru vs. Yanlış (Visual Code Comparison)

Geliştiricilerin sıklıkla düştüğü anti-pattern ile kurumsal Clean Architecture standardının yan yana karşılaştırması.

❌ KÖTÜ KOD (Anti-Pattern: HTTP Sızıntısı)

Service katmanı HTTP paketlerine bağımlı kılınmış, test edilebilirlik ve taşınabilirlik yok edilmiş:

// ⚠️ YASAK: Service içine HTTP bulaşmış!
@Service
public class UserService {

    // HATA 1: ResponseEntity dönüyor
    public ResponseEntity<ApiResponse<UserDto>> getUser(String id) {
        User user = repository.findById(id).orElse(null);
        if (user == null) {
            // HATA 2: Service içinde HTTP 404 üretiliyor
            return ResponseEntity.status(HttpStatus.NOT_FOUND).build();
        }
        // HATA 3: Service HTTP zarfını biliyor
        return ResponseEntity.ok(ApiResponse.success(toDto(user), "traceId"));
    }
}
✅ TEMİZ KOD (Clean Architecture Standardı)

Service tamamen saf Java DTO döner; Controller ise HTTP zarflamasını ve durum kodunu yönetir:

// ✅ DOĞRU: Service sadece iş mantığını işletir
@Service
public class UserService {

    public UserDto getUser(String id) {
        return repository.findById(id)
                .map(this::toDto)
                .orElseThrow(() -> new ResourceNotFoundException("User", "id", id));
    }
}

// Controller HTTP zarfını ve statüsünü atar
@GetMapping("/{id}")
public ResponseEntity<ApiResponse<UserDto>> getUser(@PathVariable String id) {
    UserDto user = userService.getUser(id);
    String traceId = MDC.get("traceId");
    return ResponseEntity.ok(ApiResponse.success(user, traceId));
}
AŞAMA 3

OpenAPIConfig (JWT Bearer & OAS 3.1)

Swagger UI üzerinde 'Authorize' butonunu aktifleştiren, JWT Bearer Token şemasını ve kurumsal API meta bilgilerini tanımlayan merkezi konfigürasyon.

CONFIGURATION com.enterprise.common.config.OpenAPIConfig.java 
package com.enterprise.common.config;

import io.swagger.v3.oas.models.Components;
import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.info.License;
import io.swagger.v3.oas.models.security.SecurityRequirement;
import io.swagger.v3.oas.models.security.SecurityScheme;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class OpenAPIConfig {

    public static final String SECURITY_SCHEME_NAME = "BearerAuth";

    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("Enterprise Core REST API Services")
                        .version("v1.0.0")
                        .description("Standardized Spring Boot 4.1.1 REST API Documentation with RFC 7807 ProblemDetail and Clean Boundary Isolation.")
                        .contact(new Contact()
                                .name("API Architecture Governance Team")
                                .email("api-core@enterprise.com"))
                        .license(new License()
                                .name("MIT License")
                                .url("https://opensource.org/licenses/MIT")))
                .addSecurityItem(new SecurityRequirement().addList(SECURITY_SCHEME_NAME))
                .components(new Components()
                        .addSecuritySchemes(SECURITY_SCHEME_NAME,
                                new SecurityScheme()
                                        .name(SECURITY_SCHEME_NAME)
                                        .type(SecurityScheme.Type.HTTP)
                                        .scheme("bearer")
                                        .bearerFormat("JWT")
                                        .description("JWT Bearer token formatında yetkilendirme başlığı: 'Bearer {token}'")));
    }
}

Anotasyon Hijyeni & Kurumsal Meta-Anotasyonlar

Tekrar eden Swagger yanıt tanımlarını tek satıra indiren ve RFC 7807 ProblemDetail şemalarını otomatik bağlayan bileşik anotasyonlar.

META-ANNOTATION com.enterprise.common.openapi.ApiCommonResponses.java 
package com.enterprise.common.openapi;

import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import org.springframework.http.ProblemDetail;

import java.lang.annotation.*;

/**
 * Tüm endpoint'lerde ortak olan 400, 401, 403 ve 500 RFC 7807 hata şemalarını tek seferde ekler.
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@ApiResponses({
        @ApiResponse(
                responseCode = "400",
                description = "Bad Request / Validasyon Hatası (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        ),
        @ApiResponse(
                responseCode = "401",
                description = "Unauthorized / Kimlik Doğrulama Başarısız (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        ),
        @ApiResponse(
                responseCode = "403",
                description = "Forbidden / Yetkisiz Erişim (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        ),
        @ApiResponse(
                responseCode = "500",
                description = "Internal Server Error / Beklenmeyen Sunucu Hatası (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        )
})
public @interface ApiCommonResponses {
}
META-ANNOTATION com.enterprise.common.openapi.ApiGetResponse.java 
package com.enterprise.common.openapi;

import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import org.springframework.core.annotation.AliasFor;
import org.springframework.http.ProblemDetail;

import java.lang.annotation.*;

/**
 * 200 OK + 404 Not Found + Ortak RFC 7807 Hata Yanıtlarını tek satırda bağlar.
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@ApiCommonResponses
@ApiResponses({
        @ApiResponse(
                responseCode = "200",
                description = "Kayıt başarıyla getirildi"
        ),
        @ApiResponse(
                responseCode = "404",
                description = "İstenen kaynak bulunamadı (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        )
})
public @interface ApiGetResponse {
    @AliasFor(annotation = ApiResponse.class, attribute = "description")
    String description() default "Kayıt başarıyla getirildi";
}
META-ANNOTATION com.enterprise.common.openapi.ApiCreateResponse.java 
package com.enterprise.common.openapi;

import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import org.springframework.core.annotation.AliasFor;
import org.springframework.http.ProblemDetail;

import java.lang.annotation.*;

/**
 * 201 Created + 409 Conflict (Duplicate resource) + Ortak RFC 7807 Hata Yanıtları.
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@ApiCommonResponses
@ApiResponses({
        @ApiResponse(
                responseCode = "201",
                description = "Kaynak başarıyla oluşturuldu"
        ),
        @ApiResponse(
                responseCode = "409",
                description = "Veritabanı kısıt/çakışma hatası (Duplicate resource) (RFC 7807)",
                content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class))
        )
})
public @interface ApiCreateResponse {
    @AliasFor(annotation = ApiResponse.class, attribute = "description")
    String description() default "Kaynak başarıyla oluşturuldu";
}
META-ANNOTATION com.enterprise.common.openapi.ApiDeleteResponse.java 
package com.enterprise.common.openapi;

}

Temiz REST Controller Implementasyonu

Meta-anotasyonlar ile süslenmiş, HTTP izolasyonunu eksiksiz uygulayan referans Controller sınıfı.

CONTROLLER com.enterprise.coreapi.controller.UserController.java 
package com.enterprise.coreapi.controller;

import com.enterprise.common.filter.TraceIdFilter;
import com.enterprise.common.openapi.*;
import com.enterprise.common.response.ApiResponse;
import com.enterprise.common.response.PageResponse;
import com.enterprise.coreapi.dto.CreateUserRequest;
import com.enterprise.coreapi.dto.UserDto;
import com.enterprise.coreapi.service.UserService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.slf4j.MDC;
import org.springframework.data.domain.Pageable;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/users")
@RequiredArgsConstructor
@Tag(name = "User Management", description = "Kullanıcı profil, listeleme ve kayıt operasyonları")
public class UserController {

    private final UserService userService;

    // 1. TEKİL GETİRME: 200 OK + 404 + 400 + 401 + 403 + 500
    @GetMapping("/{id}")
    @Operation(summary = "Kullanıcı Detayı", description = "Verilen ID'ye ait kullanıcının profilini getirir.")
    @ApiGetResponse(description = "Kullanıcı başarıyla bulundu")
    public ResponseEntity<ApiResponse<UserDto>> getUser(@PathVariable String id) {
        UserDto user = userService.getById(id);
        String traceId = MDC.get(TraceIdFilter.MDC_TRACE_ID_KEY);
        return ResponseEntity.ok(ApiResponse.success(user, traceId));
    }

    // 2. SAYFALANMIŞ LİSTELEME: 200 OK + 400 + 401 + 403 + 500
    @GetMapping
    @Operation(summary = "Sayfalanmış Kullanıcı Listesi", description = "Sistemdeki kullanıcıları sayfalar halinde getirir.")
    @ApiCommonResponses
    public ResponseEntity<ApiResponse<PageResponse<UserDto>>> getUsers(Pageable pageable) {
        PageResponse<UserDto> page = PageResponse.of(userService.getAll(pageable));
        String traceId = MDC.get(TraceIdFilter.MDC_TRACE_ID_KEY);
        return ResponseEntity.ok(ApiResponse.success(page, traceId));
    }

    // 3. YENİ KAYIT: 201 CREATED + 409 + 400 + 401 + 403 + 500
    @PostMapping
    @Operation(summary = "Yeni Kullanıcı Oluştur", description = "Sistemde yeni bir kullanıcı kaydı açar.")
    @ApiCreateResponse(description = "Kullanıcı hesabı başarıyla açıldı")
    public ResponseEntity<ApiResponse<UserDto>> createUser(@Valid @RequestBody CreateUserRequest request) {
        UserDto created = userService.create(request);
        String traceId = MDC.get(TraceIdFilter.MDC_TRACE_ID_KEY);
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(ApiResponse.success(created, "User created successfully", traceId));
    }

    // 4. SİLME: 204 NO CONTENT + 404 + 400 + 401 + 403 + 500
    @DeleteMapping("/{id}")
    @Operation(summary = "Kullanıcı Sil", description = "ID'si verilen kullanıcıyı sistemden siler.")
    @ApiDeleteResponse
    public ResponseEntity<Void> deleteUser(@PathVariable String id) {
        userService.delete(id);
        return ResponseEntity.noContent().build();
    }
}

Uygulama ayağa kalktığında /swagger-ui.html adresinde üretilen OpenAPI sözleşmesinin anatomisi.

🌐 Swagger UI Erişim Bilgileri

  • OpenAPI v3 JSON Spesifikasyonu: http://localhost:8080/v3/api-docs

Kurumsal Mimari Kontrol Listesi (Developer Checklist)

Controller ve Service sınıflarını commit etmeden önce kontrol edilmesi zorunlu mimari kurallar.

  • ✓
    Service Katmanı HTTP İzolasyonu: Service sınıflarında org.springframework.http.*, ResponseEntity, HttpStatus veya ApiResponse import'u kesinlikle bulunmuyor mu?
  • ✓
    İstisna Yönetimi Sorumluluğu: Service katmanı bulunamayan veya çakışan kayıtlarda HTTP üretmek yerine domain exception fırlatıyor mu (ResourceNotFoundException, BusinessException)?
  • ✓
    Meta-Anotasyon Kullanımı: Endpoint'ler üzerinde ham ve tekrar eden @ApiResponses blokları yerine @ApiGetResponse, @ApiCreateResponse veya @ApiCommonResponses kullanıldı mı?
  • ✓
    OpenAPI Güvenlik Tanımı: OpenAPIConfig sınıfı projeye dahil edilip JWT BearerAuth şeması tanımlandı mı?
  • ✓
    Delete Operasyonları Statüsü: Silme endpoint'leri gövde dönmüyorsa 204 NO CONTENT statüsüyle dönüyor mu?
